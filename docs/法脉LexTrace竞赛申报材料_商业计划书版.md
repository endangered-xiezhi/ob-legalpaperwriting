# 法脉 LexTrace 竞赛申报材料（商业计划书版）

## 一句话定位

**法脉 LexTrace——从一句原文到一个研究问题的可追溯法学研究工作台。**

产品首先服务“第一次进入陌生法学议题”的研究生：先帮助用户听懂主要观点和研究路径，再把真正触发思考的原文句子转化为可核验的研究问题、争议关系与写作提纲。

## 二、作品构想（1000字以内）

**作品名称：法脉 LexTrace——从一句原文到研究问题的可追溯法学研究智能体**

**1．想解决的问题**

本作品首先面向初次进入陌生议题、准备课程论文、开题或综述的法学研究生，并兼顾跨学科研究者。数据库解决“找到论文”，大模型解决“快速回答”，但两者之间仍缺少可靠路径：用户如何迅速听懂争议，又如何从一句真正有启发的原文形成自己的问题和论证。教师是次级用户，第一版主要帮助其组织专题书单、研讨材料和核验学生来源，不替代教师判断。

**2．核心产品**

LexTrace采用“入门—筛选—锚点—建图—提纲—复核”六步流程。用户填写知识基础、任务和时间预算，系统通过具体案例、递进问题和三档口头表达生成入门地图；随后在授权范围内完成采集、去重、PDF／OCR解析和纳入反馈。下一版本接入Zotero摘录：关键句、页码、书目信息和PDF回跳链接同步为“灵感锚点”。智能体不续写论文，而是围绕该句生成“为何重要—能形成什么问题—支持或反驳何种命题—连接哪些文献—进入哪个提纲节点”。Obsidian保存研究卡和脉络，本机网页负责导览、筛选和研究包导出。

**3．差异化价值**

LexTrace不是论文生成器，而是研究启动与证据管理工具。其差异首先是句子级：既证明观点来自哪篇论文，也记录哪句话触发了何种判断；其次是命题级：比较具体结论、理由、条件和反驳，不把学者固定为简单阵营；再次是本地优先：PDF、摘录和笔记留在本机，无法核验的内容统一标记。Zotero负责精确摘录，Obsidian负责跨文献脉络，LexTrace把二者转化为研究行动。

**4．实现与验证**

目前原型已沉淀514个知识产权论文记录和七个争议专题，并实现知网采集样板、摘要初筛、Obsidian自动目录、本机镜像、Agent任务单、引注和研究包导出。下一阶段完成Zotero适配器、灵感锚点卡和教师专题包。验证采用真实任务：研究生完成陌生议题口述、提出问题并形成有来源的提纲；教师生成研讨书单和讨论题。指标包括形成有效问题的时间、观点覆盖率、错误归因率、摘录回溯率和人工修改量，并与通用大模型问答对照，公开失败案例与边界。

**5．预期成果**

☑ 法律智能体　☐ 实验设计报告　☐ 实验报告　☐ 论文　☐ 其他

## 三、团队分工与完成计划（500字以内）

**1．团队与分工**

团队具备法学研究、Python采集、PDF／OCR处理、大模型工作流和Obsidian知识库搭建经验，曾在腾讯开悟相关比赛获奖并进入星瀚杯决赛。法学研究组负责入门问题链、观点卡和争议关系标准；数据组负责授权采集、去重、页码与来源映射；产品与智能体组负责Zotero—Obsidian衔接、灵感锚点、前端和Agent任务；测试组负责用户测试、错误归因与失败案例审计。

**2．准备与计划**

项目已有514个知识产权论文记录、七个争议专题，以及可运行的采集、空白样板、自动目录和本机工作台。第1—2周访谈研究生与教师，固定陌生领域入门模板和灵感锚点字段；第3—4周完成Zotero摘录导入、页码回跳和去重；第5—6周打通“关键句—研究问题—争议矩阵—写作提纲”；第7周试做教师研讨包和学生研究审计；第8周开展对照测试并迭代。主要风险是OCR错序、摘录脱离上下文、经典文献召回不足及教师需求差异，分别通过质量分级、上下文窗口、引文反查、人工确认和可配置模板控制。不能核验的内容只进入待审核区，不进入正式结论。

## 四、建议的产品页面排布

### 1．开始一项研究

- 填写“我已经知道什么、要完成什么、还有多少时间”。
- 选择课程论文、开题、文献综述、课堂研讨或教师专题包。
- 输出推荐阅读深度，而不是给所有用户同一套复杂页面。

### 2．陌生领域快速入门

- 用一个贯穿案例解释该领域为什么产生争议。
- 按递进问题展示“担心什么—通俗解释—典型观点—最强反问”。
- 提供30秒、90秒和3分钟口头表达。
- 入口始终可回到代表论文，不把入门解释冒充论文原话。

### 3．论文发现与筛选

- 知网或本地PDF导入、期刊卡片、研究画像。
- 标题摘要初筛，提供纳入、排除和待定反馈。
- 重复论文优先链接既有记录，不重复制卡。

### 4．灵感锚点（新增核心页）

每条锚点至少包含：

- Zotero短摘录、页码、citekey与PDF回跳链接；
- 摘录上下文和核验状态；
- “这句话为什么值得记”；
- 可提出的研究问题；
- 可支持、限制或反驳的命题；
- 可连接的其他文献；
- 可进入的提纲节点。

产品按钮不应写“AI续写”，而应写“把这句话变成研究问题”“寻找反方材料”“加入论证节点”。

### 5．争议与写作工作台

- 观点关系建立在命题之间，而不是只画作者关系图。
- 提纲中的每个关键节点必须至少绑定一篇论文或一个灵感锚点。
- 明确区分作者原文、用户判断和Agent建议。

### 6．研究包与教师模式

- 学生端导出：研究问题、筛选记录、灵感锚点、提纲、引注和待核验项。
- 教师端导出：分层书单、课前导读、对立观点、研讨问题和学生来源审计。
- 教师端不承诺替教师总结整个学科，只减少组织材料和核对来源的机械劳动。

## 六、适合答辩时使用的商业表达

### 30秒产品介绍

数据库帮助研究生找到论文，大模型帮助他快速得到答案，但真正的研究往往始于论文中某一句让人产生疑问的话。LexTrace首先让初学者听懂一个陌生议题，再把Zotero中的关键摘录变成可追溯的研究问题、争议关系和写作节点。它不替用户生成论文，而是缩短从“我不了解这个领域”到“我知道下一步该研究什么”的时间。

### 对教师价值的谨慎表述

我们不把教师定义为第一版的核心付费或高频用户，也不声称智能体能够替代教师的学术判断。教师端首先解决三个可验证的小问题：快速组织分层书单、为研讨课配置对立观点、检查学生的观点是否真的能回到原文。验证这三个场景后，再决定是否扩展到课题组协作和课程知识库。

### 产品壁垒

LexTrace的壁垒不是单一模型，而是四层结合：合法来源与去重流程、适合法学论证的结构化字段、Zotero句子级证据与Obsidian跨文献脉络、以及经过真实研究任务验证的失败处理规则。模型可以替换，研究过程和可复核数据资产会持续积累。
