### 1.1 交付原则与合规解耦机制
根据竞赛材料规范、数据安全及学术出版著作权合规要求，本参赛作品采用**“核心智能体与工程资产全量交付，原始学术文献脱敏解耦”**的轻量化合规交付机制：
- **完整交付的核心工程与智能体组件**：
  1. **全栈智能体引擎代码**：
     - **知网/网核学术采集器 (`cnki_crawler/`)**：包含作者模式（Author Mode）与期刊模式（Journal Mode）双轨采集主程序 `run_spider.py`、EndNote 格式自动解析、防爬应对机制及自动化元数据提取器；
     - **本地数据穿透与系统服务桥接器 (`local_bridge/`)**：基于 Python 轻量服务（监听 `8765` 端口），打通 Web 工作台与本地操作系统文件交互，提供安全、低延迟的本地化数据通信；
     - **Next.js 15 / Vinext 响应式学术工作台源码 (`app/`)**：包含完全重构的温润宣纸色学术排版组件 `obsidian-workbench.tsx`、全局样式系统 `globals.css` 及自动化预渲染脚本；
  2. **智能体 Prompt 清单与 SOP 执行规范**：
     - 法学论文整理标准化作业程序（SOP 任务单）；
     - 核心 Prompt 1（论文精读整理与五维卡片生成）；
     - 核心 Prompt 2（学术争议结构化拆解与对立矩阵生成）；
     - 核心 Prompt 3（立法沿革与学术发展趋势总结）；
     - 无状态大模型 API 交互中枢（支持 OpenAI 格式、DeepSeek 及本地 Ollama）；
  3. **自动化测试套件与持续集成管线**：
     - 内置 Node.js SSR/静态预渲染断言测试（`tests/rendered-html.test.mjs`，2 项断言 100% 通过）；
     - Python 数据桥接自动化测试（`tests/test_bridge.py`，7 项接口测试 100% 通过）；
     - GitHub Actions 云端持续集成工作流（`.github/workflows/ci.yml`）；
  4. **全套一键部署脚本**：
     - 面向零代码基础用户的 macOS 双击 `.command` 专属引导器；

## 第二部分：系统架构与功能说明书

### 2.1 整体设计哲学与痛点解决逻辑
在法学学术研究、研究生开题、研讨课备课及学位论文撰写过程中，“初入陌生法学细分领域”是每一个研究者必须跨越的高门槛。当前通用大语言模型（如 ChatGPT、Claude）存在两大不可逾越的学术死穴：
1. **“一本正经的学术伪幻觉”**：通用大模型经常捏造不存在的法条、虚构期刊卷期号，或在没有真实文本依据的情况下张冠李戴学说观点；
2. **“脱离证据链的空中楼阁”**：大模型生成的观点无法直接穿透追溯至学者论文的具体页码与法学论证段落，研究者无法将大模型的输出作为撰写正规学术论文的立论基础。

**法脉 LexTrace** 坚持**“不替代学者精读，但重塑精读前的认知构建与证据管理”**的核心宗旨。系统基于**显式页码约束（Explicit Page Anchor）**与**转化性学术图谱（Transformative Academic Graph）**，构建从“数据自动化摄入 ➔ 结构化提炼 ➔ 争议焦点聚合 ➔ 灵感锚点生成 ➔ 论文写作提纲”的全链路闭环体系。

### 2.2 MECE 四层系统架构设计
系统严格遵循相互独立、完全穷尽（MECE）的软件工程规范，解构为四大纵向支撑层：

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                 第四层：用户交互与学术工作台呈现层 (Presentation Layer)             │
│   Web 仪表盘 (Next.js 15) │ 15篇/页文献分页 │ 争议焦点/作者路径 │ 检索式/阅读历史与Fork  │
├─────────────────────────────────────────────────────────────────────────────┤
│                 第三层：智能体推理与 Prompt 枢纽层 (Agent & Reasoning Layer)        │
│   法学整理SOP任务单 │ 3大核心 Prompt (精读/争议/趋势) │ 无状态大模型 API 交互窗口  │
├─────────────────────────────────────────────────────────────────────────────┤
│                 第二层：知识图谱与双链双向穿透层 (Knowledge & Link Layer)           │
│   Obsidian 双链网络 │ PDF++ 逐页标柱穿透 │ YAML 元数据体系 │ Zotero 灵感锚点     │
├─────────────────────────────────────────────────────────────────────────────┤
│                 第一层：数据全自动采集与摄入预处理层 (Ingestion & Extraction Layer)   │
│   CNKI 双模爬虫 (作者/期刊) │ PyMuPDF 显式分页标柱 │ EndNote/RIS 解析 │ 待审核队列   │
└─────────────────────────────────────────────────────────────────────────────┘
```

#### 层级 1：数据全自动采集与摄入预处理层 (Ingestion Layer)
- **CNKI 双模定向采集引擎**：
  - **作者全量模式 (Author Mode)**：针对特定法学权威学者（如王迁、崔国斌、蒋舸、孔祥俊等）进行穿透式检索，采集其在各时期发表的代表性论文；
  - **期刊核心模式 (Journal Mode)**：锁定 CLSCI 16 种法学核心期刊（《法学研究》《中国法学》《中外法学》等）与 CSSCI 来源刊，过滤短篇书评与消息，精准下载原创研究长文。
- **PyMuPDF 显式分页标柱引擎**：
  - 针对下载的 PDF 格式学术论文，提取全文字符流并强制插入显式分页标记 `[[PDF_PAGE:n]]`；
  - 保留论文标题、摘要、关键词、基金项目、作者机构及期刊卷期页码等结构化元数据；
- **防错与待审机制**：若抓取到的文献存在元数据缺失或 OCR 乱码，自动移入“待审核队列（Pending Triage Queue）”，绝不污染正式知识库。

#### 层级 2：知识图谱与双链双向穿透层 (Knowledge Layer)
- **本地优先（Local-First）双链知识底座**：
  - 采用标准 Markdown 格式与 YAML Frontmatter 存储，解耦于任何商业云服务，研究者笔记完全保存在个人本地硬盘；
  - 每篇文献卡片内生关联其所属部门法分类、年度索引、研究主题及对应学者的核心观点。
- **PDF++ 原生分屏双向穿透技术**：
  - 左侧展示结构化精读卡，右侧分屏悬挂原版 PDF；
  - 点击卡片内的任一金句或页码锚点，PDF 视窗自动毫秒级精准跳至对应页码并高亮对应论证段落，实现“观点—证据”毫秒级复核。
- **Zotero 灵感锚点连接器**：
  - 将学者在 Zotero 中的划词批注同步提取为“灵感锚点卡”，记录短摘录、citekey、上下文及核验状态。

#### 层级 3：智能体推理与 Prompt 枢纽层 (Agent Layer)
- **法学论文整理 SOP 规范**：
  - 制定标准化的 5 大维度提取范式：**【问题的提出】**（现实痛点与立法空白）、**【学说争议】**（否定说 vs. 肯定说 vs. 折中说）、**【制度构建方案】**（解释论或立法论构想）、**【核心论证链条】**（法条依据与法理演绎）、**【核心金句及精确页码】**。
- **三大场景化专业 Prompt 矩阵**：
  1. `Prompt 1：法学论文结构化整理与深度卡片提取`：驱动大模型将论文全文转化为标准 Markdown 学术卡片；
  2. `Prompt 2：学术争议焦点与观点矩阵重构`：聚焦特定争点，提炼不同学者的对立观点、核心论据与理论假设；
  3. `Prompt 3：学术发展脉络与前沿趋势研判`：宏观剖析某一法域在历次修法背景下的学术演进轨迹与未决课题。
- **无状态 API 交互网关**：
  - 前端工作台内置通用 API 交互窗口，支持用户配置自有的 DeepSeek、Claude、OpenAI 或本地 Ollama 接口，实现 Prompt 与材料的一键组装发送。

#### 层级 4：用户交互与学术工作台呈现层 (Presentation Layer)
- **斯坦福法学评论风格（Warm Alabaster）排版系统**：
  - 采用米黄暖调（`#faf8f4`）、深松针绿（`#1a4d44`）与朱砂红点缀，正文行高拉升至 `1.75 - 1.85`，字号严格维持在 15px - 16px（标准中文五号字），极大缓解高强度学术阅读的视觉疲劳。
- **全要素工作台功能组**：
  - **15篇/页学术文献分页列表**：支持按学科领域、作者、年份及关键词快速筛选，清晰展示核心论题与期刊卷期；
  - **阅读历史与 Fork 机制**：支持将重点文献一键标记为 `★ 重点` 并留存阅读足迹，解除了条目限制，支持将精选文献一键打包为研究物料；
  - **检索式记录与历史管理**：允许学者保存复杂的检索式语法（如 `主题:(知识产权) AND 核心期刊:(CLSCI)`），方便未来一键复现复用；
  - **现有争议专题与作者研究路径**：呈现 7 大争议焦点的学术交锋全貌，同时支持切换至特定学者，溯源其近十年的学术思想嬗变。

## 第三部分：AI辅助开发与原创性说明

### 3.1 原创性与自主研发声明
本参赛作品由法脉智能科研团队独立完成全部需求定义、法学知识工程架构、底层爬虫编写、前后端开发及测试工作：
1. **核心算法与爬虫代码原创**：针对中国知网（CNKI）复杂翻页与防爬机制的解析算法、EndNote 格式自动转换程序、PyMuPDF 页面标柱插入逻辑均系团队自主编写，未采用任何商业爬虫黑盒；
2. **法学结构化字段与 SOP 体系原创**：将传统法学研读经验抽象为“问题提出、学说争议、制度方案、显式页码”五维字段，及基于争议焦点对比学者理论前提的方法论，系团队结合多年法学专业训练完全独立研发；
3. **前端工作台与双链库模板原创**：从零构建的 Next.js 15 / TypeScript 学术工作台，创新的 15 篇紧凑学术排版、阅读历史与 Fork 机制、争议专题与作者路径看板，均拥有独立自主的知识产权。

### 3.2 团队学术背景与竞赛积淀
团队成员具备深厚的法学理论功底与扎实的计算机开发技能：
- 团队核心成员系统学习过网络爬虫与分布式数据采集技术，曾参与**腾讯开悟（Tencent Kaiwu）**相关算法赛事并获奖；
- 在**“星瀚杯”全国人工智能创新大赛**中，团队研发的“企业三会治理智能合规 Agent”成功晋级全国总决赛；
- 成员目前专注于法学知识工程与司法大数据研究，深刻理解高校法学学者与法学生在论文开题、文献研读中的实际痛点。

### 3.3 AI 辅助开发边界与伦理合规说明
团队严格遵循学术诚信与开源技术规范，清晰界定 AI 工具的使用边界：
- **AI 辅助介入环节（仅限工程辅助工具）**：
  - 在前端开发过程中，利用 AI 代码补全工具对部分 UI 组件的 CSS 响应式样式、TypeScript 接口类型声明进行了格式辅助；
  - 辅助生成了针对边缘异常情况的单元测试用例桩代码（Mock Data）。
- **完全自主研发环节（严禁 AI 越俎代庖）**：

## 第四部分：功能展示与说明材料

### 4.1 功能模块一：知网论文收集与检索式智能记录
- **功能目标**：终结传统知网检索下载繁琐、命名混乱、检索历史不可沉淀的痛点。
- **核心特性**：
  1. **双模采集配置**：支持“作者模式（抓取知名学者历年论文全集）”与“期刊模式（限定 CLSCI 16 种法学核心期刊）”快速切换；
  2. **检索式持久化记录**：工作台内置“检索式记录”模块，用户可输入复杂检索逻辑并点击 `💾 保存当前检索式`。系统自动记录时间戳与检索条件，支持历史检索式一键载入与复现，让文献调研路径完全可复核；
  3. **初筛与纳入流水线**：直观展示从“01 设定检索式” ➔ “02 抓取文献元数据” ➔ “03 标题与摘要初筛” ➔ “04 自动入库与生成待处理样板”的全自动化时间轴，非合规或不可信文献在初筛阶段即可剔除。

### 4.2 功能模块二：学术文献卡片与 15 篇/页沉浸式研读看板
- **功能目标**：提供符合顶级期刊阅览体验的文献总览，杜绝信息过载。
- **核心特性**：
  1. **15 篇/页黄金分页排版**：打破单页过多导致滚动疲劳或单页过少导致频繁切页的弊端，单页承载 15 篇精选文献，并在顶部与底部均设有典雅的分页控制器与快速跳页器；
  2. **多维筛选与瞬时检索**：支持按著作权法、专利法、商标法、竞争法等部门法进行标签筛选，支持按作者、年份范围及关键词即时过滤；
  3. **微型多功能操作组（`.row-action-group`）**：
     - **`★ 重点 / ☆ 收藏`**：一键将关键文献纳入持久化阅读历史与高优关注清单；
     - **`引注` 快捷复制**：一键生成符合《法学引注手册》国家标准的学术引注字符串（包含作者、篇名、刊名、年份、卷期与页码）；
     - **`+ 材料 / ✓ 已选`**：将文献纳入当前 Agent 推理的上下文物料包；
     - **`OB ↗`**：通过 Obsidian URI 协议，直接在本地 Obsidian 客户端中分屏弹窗打开对应的精读笔记与关联 PDF。

### 4.3 功能模块三：Agent Prompt 清单与 SOP 执行中枢
- **功能目标**：将优秀的法学研究方法论固化为标准化、可复制的智能体提示词规范。
- **核心特性**：
  1. **Prompt 选项卡设计**：界面采用无前缀冗余的药丸选项卡（Pill Tabs），包含：
     - `SOP 任务单`：法学论文整理与证据链复核的操作规范；
     - `1. 论文整理 Prompt`：指导大模型输出标准的五维学术卡片；
     - `2. 争议结构 Prompt`：指导大模型按“否定说/肯定说/折中说”解构学者交锋；
     - `3. 总结趋势 Prompt`：宏观分析某一立法条文在过去十年中的演进动向；
     - `API 接入窗口`：无状态大模型调用测试中枢。
  2. **API 接入与物料一键组装**：用户可在 API 窗口中配置自己的 API Key（如 OpenAI 规范或 DeepSeek 模型），工作台自动将当前勾选的文献材料与所选 Prompt 无缝拼接为标准 Payload，点击发送即可即时获得结构化研读结果。

### 4.4 功能模块四：阅读历史、重点追踪与 Fork 体系
- **功能目标**：记录研究者的思考轨迹，支持研究成果的派生与复现。
- **核心特性**：
  1. **解除条目限制**：彻底打破旧版仅能存储 8 条记录的物理瓶颈，支持无上限的学术阅读足迹追踪；
  2. **Fork 派生研究**：研究者可将特定文献或争议专题一键“Fork”至自己的私有工作分支，在此基础上进行个性化批注、补充反方论据，而不破坏原始公共文献卡片；
  3. **研究包导出**：一键将已读重点文献、引注列表、争议结构导出为完整的 Markdown/Text 研究简报，作为撰写综述的第一手素材。

### 4.5 功能模块五：现有争议专题与作者研究路径
- **功能目标**：让初学者在几分钟内看懂一个陌生法学领域的核心分歧，掌握学术领军人物的思想演进。
- **核心特性**：
  1. **现有争议专题（7大焦点）**：
     - 精准收录“视听作品独创性认定标准”、“数据产权与反不正当竞争法保护边界”、“人工智能生成物（AIGC）可版权性争论”、“标准必要专利禁令救济适用”、“商标使用与防御性注册规制”等 7 大前沿专题；
     - 采用对立矩阵形式展示各派学说的核心立论前提、关键推导步骤及制度妥协方案。
  2. **作者研究路径 (Author Trajectories)**：
     - 取代单一的机构检索，聚焦具体权威学者（如王迁教授、崔国斌教授等）近十年间发表的系列论文；
     - 梳理学者在不同历史修法节点（如著作权法第三次修改前后）对于同一概念之解释立场的深化与转向，帮助研究生把握学术前沿的真实动态。

### 4.6 功能模块六：法规与典型案例专属模块
- **功能目标**：打破法学学术文献与实务裁判之间的信息壁垒。
- **核心特性**：
  1. **穿透式规范依据索引**：每一篇文献卡片与争议专题，均明确标注其对应的法律渊源条文（如《著作权法》第十七条、《反不正当竞争法》第二条等）；
  2. **指导性案例穿透联动**：收录最高人民法院指导性案例及知识产权法庭典型裁判要旨，实现“学术学说批判 ➔ 司法实务立场 ➔ 典型案件判决”的三位一体互动对照。
