一、交付原则与知识资产脱敏解耦机制

为严格遵守国家知识产权出版法规、数据合规标准及学术诚信规范，同时保证大赛评审专家能够在轻量化环境下无障碍运行测试，本参赛作品采用“核心智能体与工程代码全量交付，原始版权文献脱敏解耦”的交付机制：

✅ 全量保留并交付的智能体资产
  • 前端学术工作台源码：Next.js 15 / TypeScript 响应式研究中枢，包含 15 篇黄金分页、争议图谱与检索式持久化模块；
  • 知网双模学术采集器：支持“作者模式”与“期刊模式”的高效 Python 爬虫引擎及防爬解析算法；
  • 本地轻量桥接服务：Python 3.11 专属系统桥接器（监听 8765 端口），打通 Web 与本地 Obsidian 笔记；
  • 三大核心法学 Prompt 与 SOP：论文整理、争议提炼、趋势洞察规范及无状态 API 交互窗口；
  • 端到端自动化测试套件：Node.js SSR 预渲染测试与 Python 桥接通信测试。
🔒 依法合规解耦不打包的内容
  • 商业期刊 PDF 全文二进制原件：因涉及中国知网（CNKI）及各大法学核心期刊排版版式著作权，交付包中不打包随附商业论文原文文件；
  • 海量原始 Markdown 笔记：为避免交付包膨胀至数 GB，仅提供元数据样板、数据契约规范（Schema）及 7 大争议专题框架；
  • 一键环境复现机制：评委或用户克隆仓库后，可通过内置的双模采集器或一键挂载脚本，毫秒级复现个人本地专属文献库。
💡 为什么采用 Obsidian + PDF++ 原生一体化，彻底摒弃 Zotero？
团队在早期开发中曾尝试接入 Zotero，但发现跨软件数据同步存在严重割裂：研究者在 Zotero 中批注后必须经过繁琐的数据转换才能导入笔记，且无法直接在单一界面完成原版 PDF 与知识卡片的分屏对照。为此，团队研发了基于 Obsidian + 原生 PDF++ 插件的零割裂工作流：通过在 PDF 字符流中显式插入 [[PDF_PAGE:n]] 标柱，使阅读批注、高亮定位、页码溯源与大纲写作 100% 聚合在单一软件内完成，彻底告别外部工具碎片化！
