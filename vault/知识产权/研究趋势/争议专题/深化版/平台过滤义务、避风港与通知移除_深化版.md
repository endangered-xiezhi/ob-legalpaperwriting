# 平台过滤义务、避风港与通知移除：争议深化版

> [!summary] 核心判断
> 平台责任不能继续围绕“中立平台／非中立平台”的身份二分。推荐、生成、存储、API 接入和内容分发具有不同控制结构。更可操作的分析是：**平台实施了什么帮助或参与行为—获得何种具体知识—具备何种识别和控制能力—权利人是否完成协力—何种措施在成本、准确率和误伤之间合比例**。

> [!important] 证据边界
> 本页整合 [[研究趋势/争议专题/平台过滤义务、避风港与通知移除|原争议专题]]、[[研究趋势/面试专题/著作权AI与商标法研究路径_面试表达版_2026-07-23|著作权 AI 与商标法增量报告]] 及库内平台责任论文。平台责任的结论高度依赖服务功能和技术事实，不能仅由“平台”“算法”或“生成式 AI”名称推导。

## 一、问题的提出：为什么“平台有没有能力”仍不足以决定责任

### 1. 六种经常被统称为平台的主体

| 主体 | 主要控制对象 | 责任分析重点 |
|---|---|---|
| 基础模型开发者 | 训练数据、模型架构、权重 | 数据来源、模型设计、可预见复现 |
| 开放权重提供者 | 权重发布、许可证、文档 | 对下游控制有限，风险提示和许可范围 |
| API／模型接入服务者 | 调用权限、输入输出、日志 | 访问管理、具体通知、输出控制 |
| 生成式服务平台 | 界面、系统提示、过滤、输出 | 持续控制、获利、内容生成参与 |
| 内容存储／分发平台 | 上传、推荐、传播、变现 | 具体知识、重复侵权、必要措施 |
| 应用开发者／商业利用者 | 具体场景、微调、用户交互 | 对侵权用途的直接设计和收益 |

把这些主体都套用同一避风港或同一主动审查义务，会同时产生过度免责与过度责任。

### 2. 五个必须分层的法律问题

1. 平台是否直接实施受控行为，还是仅为用户提供技术帮助？
2. 平台知道或应知的是“内容相似”，还是权属、许可和合理使用意义上的侵权？
3. 通知是否足以改变平台的信息状态？
4. 未采取措施是失去免责，还是已经满足侵权责任要件？
5. 必要措施是删除、断链、限制账号、停止变现、定向过滤还是普遍监控？

### 3. “技术上可以”与“法律上应当”之间的缺口

技术能力只说明平台可能是较低成本避免者；法律义务还需考察：

- 是否掌握判断权属和许可所需的信息；
- 识别准确率和假阳性；
- 是否会删除评论、合理使用和公共领域内容；
- 措施对用户表达和竞争的影响；
- 权利人是否提供可靠特征与权属材料；
- 平台与损害之间的因果贡献。

## 二、学术谱系：从被动安全港到定向、动态必要措施

### 阶段一：通知删除与安全港的被动模型

早期平台通常被理解为存储、链接或信息定位服务者。规则核心是：

- 平台在符合条件时获得责任限制；
- 权利人通过通知具体化侵权信息；
- 平台采取删除、断链等措施；
- 用户通过反通知恢复内容。

争议集中于通知的有效性、“红旗标准”和未响应后果。

### 阶段二：算法推荐和深度介入提高“应知”争议

- [[论文库/论算法推荐的版权中立性_崔国斌|崔国斌]]指出，推荐能力不等于法律侵权识别能力，算法处理仍可能保持版权中立。
- [[论文库/网络版权内容过滤措施的言论保护审查_崔国斌|崔国斌]]从误伤合法表达和比例性限制过滤。
- [[论文库/网络存储空间服务提供者的注意义务新解_王杰|王杰]]、[[论文库/“通知—删除”规则的结构扩张与适用限制_王杰|王杰]]说明通知规则已在实践中由免责条件向归责工具扩张。

平台的推荐、变现和运营介入成为提高注意义务的事实，但能否直接推定应知仍有争议。

### 阶段三：定向过滤成为中间方案

- [[论文库/著作权侵权平台责任的关键问题及其化解：过错认定与必要措施_王迁|王迁]]坚持直接／间接责任和过错结构，同时承认权利人提供特征库、重复侵权且成本合理时可以要求定向过滤。
- [[论文库/网络著作权侵权规则的守正与创新——立法论与解释论的二元视角分析_孔祥俊|孔祥俊]]反对通过概括知情或司法创设普遍监控改写法定结构。
- [[论文库/论“避风港规则”改革的正当性错配_刘维|刘维]]质疑仅以技术升级、平台规模或服务公开性推动全面安全港改革。

讨论从“删不删”推进到何时防止重复上传以及权利人协力。

### 阶段四：生成式 AI 使义务前移到数据、模型和输出

- [[论文库/试论生成式人工智能服务提供者的合理注意义务_吴汉东|吴汉东]]按数据获取、内容过滤和平台管理配置合理注意义务。
- [[论文库/生成式人工智能服务输出侵犯版权内容的救济研究_王杰|王杰]]区分服务者与输出商业利用者，反对将全部责任集中于平台。
- 新增研究进一步按模型开发、API、生成服务和内容分发拆分控制结构，并讨论来源记录、生成标识、持续测试和模型更新。

平台责任由“接到通知后删除”扩展为数据获取—模型设计—输出风险—传播处置的动态义务链。

## 三、争议板块一：算法推荐或生成能力能否推定“应知”

### 1. 能力匹配路径

**论证链条**：

1. 平台设计算法、控制数据和输出；
2. 平台从高风险活动中持续获利；
3. 自动化使侵权规模化，事后删除不足以预防；
4. 因此注意义务应随控制、收益和风险能力上升。

**优势**：回应现代平台不再是纯被动管道的事实。

**难点**：“能识别内容相似”与“能判断法律侵权”并不相同。许可、合理使用、权属链和保护期通常不在模型可见信息中。

### 2. 算法中立／法理限缩路径

**论证链条**：

1. 推荐和生成是自动化内容处理方式；
2. 技术先进不等于平台知道每一项权属和许可状态；
3. 间接责任仍要求帮助行为、过错和因果关系；
4. 过度推定会形成一般监控和寒蝉效应。

**优势**：维护请求权基础和合法表达空间。

**难点**：若平台主动微调以复现热门作品、掌握高准确率指纹并反复收到完整通知，继续以中立身份抗辩会忽略实际控制。

### 3. 综合判断：控制能力是义务变量，不是责任替代品

判断“应知”时应考察：

- 平台是否主动选择、编辑、微调或推广特定内容；
- 风险是否特定且反复，而非抽象存在；
- 是否获得完整通知、判决、权利指纹或许可状态；
- 平台能否以合理成本识别和处理；
- 平台是否通过变现、排名或定向推广扩大损害；
- 采取措施是否会大量误伤合法使用。

## 四、争议板块二：通知删除是免责条件还是归责规则

### 1. 免责结构

在严格教义结构中：

- 通知删除规定主要提供责任限制；
- 不满足安全港只意味着失去免责；
- 原告仍须证明平台实施帮助行为、具有过错、存在因果关系和损害；
- 安全港不是独立请求权基础。

### 2. 信息状态改变

王杰的结构扩张观察指出，有效通知会改变平台的信息状态：

1. 通知前，平台可能只有一般风险认知；
2. 通知后，权利人提供权属、位置和侵权理由；
3. 平台若有能力却长期不采取措施，其不作为可能构成过错；
4. 因而免责与归责在实践中产生连接。

### 3. 有效通知应包含什么

- 权利人身份和权利基础；
- 被控内容的准确位置、URL、账号或可识别特征；
- 权属、授权和侵权理由的初步材料；
- 对合理使用、许可或公共领域的必要说明；
- 真实性承诺及错误通知责任；
- 可供平台采取措施的机器可读信息。

批量关键词清单、抽象作品名称或无法验证的权属主张，通常不足以把全部核验成本转嫁平台。

### 4. 未响应后的责任阶梯

| 通知质量／平台状态 | 可能后果 |
|---|---|
| 通知模糊、权属不明 | 要求补正，通常不直接推定过错 |
| 通知具体但存在合理使用争议 | 临时措施、人工复核、反通知 |
| 权属和位置明确，侵权明显 | 删除、断链或停止变现 |
| 同一作品反复侵权且特征可靠 | 定向防止再上传 |
| 平台主动参与或继续推广 | 过错和因果贡献显著上升 |

## 五、争议板块三：从个案删除到定向过滤的升级条件

### 1. 个案删除

适用于首次出现、位置明确、尚无重复风险信息的内容。其优点是干预最小，缺点是无法应对重复上传。

### 2. 定向过滤

正当性较强的条件包括：

1. 权利人提供可靠、可机器识别的作品特征；
2. 同一作品或高度确定的侵权版本反复出现；
3. 平台具有现实控制能力；
4. 措施成本与损害规模相称；
5. 有反通知、人工复核和自动恢复机制；
6. 过滤范围限于特定作品、账号或侵权模式。

### 3. 普遍主动过滤

主要风险：

- 无法识别许可、引用、戏仿和合理使用；
- 亿级内容下低比例假阳性仍会造成大规模误删；
- 提高新平台和小平台进入成本；
- 平台可能以合规为由加强内容控制；
- 实质改变法定责任结构和权利人举证分工。

因此普遍过滤应保持例外，不能由“技术上可做”直接推出。

### 4. 动态必要措施

必要措施不只是删除或过滤，还包括：

- 停止推荐和变现；
- 限制特定账号功能；
- 保全日志和证据；
- 提示用户补充许可；
- 对高风险提示或用途增加摩擦；
- 更新模型或输出策略；
- 为权利人提供批量申诉接口；
- 对错误通知和错误删除建立责任。

不同措施可以按侵权明确度、重复性和风险逐级升级。

## 六、争议板块四：权利人协力义务与用户程序保障

### 1. 为什么权利人必须协力

平台通常缺少完整的权属、授权和合理使用信息。权利人更适合提供：

- 权利登记、合同或创作证明；
- 作品特征和许可状态；
- 允许使用的例外场景；
- 重复侵权版本；
- 权利期限和地域范围。

协力义务可以降低误删，也防止权利人把全部权属核验成本外部化。

### 2. 用户为何需要反通知

用户可能基于：

- 授权；
- 合理使用；
- 公共领域；
- 独立创作；
- 错误匹配；
- 权利期限届满；
- 地域差异。

反通知、人工复核、理由说明和及时恢复是过滤义务正当性的组成部分，而非附加优惠。

### 3. 错误通知和错误删除

完整制度还要处理两类责任：

- 权利人恶意或重大过失通知造成用户损害；
- 平台明显忽视反通知、长期错误删除或歧视性执行。

只增加平台删除义务、不配置错误通知责任，会产生系统性过度删除。

## 七、争议板块五：生成式 AI 服务者的动态义务

### 1. 训练前端

- 建立数据来源和授权政策；
- 处理机器可读权利保留；
- 避免明显盗版库和泄露资料；
- 保存训练集版本与来源记录。

这些义务属于训练数据专题，不应全部塞入输出平台责任，但会影响服务者整体过错。

### 2. 模型层

- 对记忆、复现和越狱风险持续测试；
- 对已知高风险作品采取定向抑制；
- 区分基础模型、微调模型和具体应用的控制者；
- 更新后重新评估风险。

### 3. 输出层

- 处理具体通知；
- 提供生成记录和申诉渠道；
- 对明显复现或重复风险采取措施；
- 对生成内容进行适当标识；
- 不把任何相似输出自动视为侵权。

### 4. 分发和商业利用层

输出的生成者、商业使用者和分发平台可能分别承担责任。服务者原则上不应为下游一切利用承担绝对责任；但如果其主动策划、推广、变现或为侵权用途定制功能，责任会明显提高。

## 八、平台义务与算法透明、商业秘密的协调

### 1. 透明不是公开全部算法

平台可以按对象分层披露：

| 对象 | 透明内容 |
|---|---|
| 法院／监管者 | 过滤规则、日志、准确率、风险评估、内部处置 |
| 独立审计者 | 模型测试、假阳性、训练来源抽样和措施效果 |
| 权利人 | 匹配结果、处置理由、重复侵权接口 |
| 用户 | 删除理由、申诉程序、主要过滤规则和标识 |
| 公众 | 风险政策、透明报告、错误率和治理框架 |

### 2. 商业秘密不是拒绝一切说明的理由

可以通过：

- 不公开审理或证据保密；
- 独立审计；
- 抽样、摘要和统计披露；
- 对不同主体设置不同访问层级；
- 限定用途和再披露责任；

在不公开核心参数的情况下验证平台是否履行义务。

## 九、相对共识、真正未决问题与压力测试

### 1. 相对共识

- 平台身份不能替代直接／间接责任和过错要件。
- 技术控制能力会影响注意义务，但不能自动证明知识。
- 未进入安全港不等于当然侵权。
- 通知质量决定平台信息状态和合理响应范围。
- 定向措施通常比普遍监控更符合比例性。
- 权利人协力、反通知和错误恢复不可缺少。
- 模型开发、API、生成服务和内容分发应区分责任。

### 2. 真正未决问题

1. 生成式服务何时从技术帮助转为直接参与表达？
2. 推荐和变现对帮助行为、因果关系的权重多大？
3. 定向过滤从一次通知升级的重复次数和准确率阈值是什么？
4. 开放权重模型的开发者应承担多长的风险控制义务？
5. 反通知期间内容是否自动恢复，谁承担临时损害？
6. 商业秘密条件下如何验证过滤准确率和偏差？
7. 小平台是否应承担与大型平台相同的技术措施？

### 3. 压力测试

| 新事实 | 首先承压的观点 | 原因 |
|---|---|---|
| 指纹匹配准确率极高且权利状态完整 | 以不可识别反对定向过滤 | 事实基础显著减弱 |
| 合法使用需复杂语境判断 | 仅凭相似度推定应知 | 技术识别不能完成法律判断 |
| 平台主动微调以稳定复现热门作品 | 纯技术中立定位 | 控制、预见和因果贡献增强 |
| 用户端加密，平台无法读取 | 能力导向主动审查 | 缺乏现实控制能力 |
| 强制快速反通知和自动恢复 | 仅以误伤长期存在反对过滤 | 程序可降低损害，但不能消除寒蝉效应 |
| 平台收到完整判决和指纹仍持续推荐 | 纯被动删除路径 | 具体知识和帮助程度显著提高 |

## 十、解释论方案：建议采用“七项平台责任矩阵”

1. **主体功能**：开发、开放权重、API、生成、存储还是分发。
2. **行为参与**：是否选择、编辑、微调、推广或变现。
3. **信息状态**：一般风险、具体通知、判决、重复侵权或内部测试。
4. **控制能力**：能否定位、删除、限制、过滤、更新或保全证据。
5. **识别质量**：是否掌握权属、许可、合理使用和可靠特征。
6. **措施比例**：成本、准确率、误伤、申诉和对竞争的影响。
7. **因果与救济**：平台行为对损害的实际贡献及最小有效措施。

该矩阵的意义是：平台能力只进入第三至第六项，不能替代第一、第二和第七项的责任证明。

## 十二、面试问题模块

### 1. 基础问题

1. 算法推荐是否意味着平台“应知”侵权？
2. 平台不满足避风港条件是否当然承担赔偿责任？
3. 通知删除是免责规则还是归责规则？
4. 何时可以要求防止重复上传？
5. 是否应对生成式 AI 施加主动过滤义务？
6. 过滤义务如何避免误伤合理使用？
7. 平台商业秘密能否对抗算法审计？

### 2. 30 秒回答

> 我不赞成以“平台中立”或“平台有能力”直接得出结论。平台责任应按主体功能、行为参与、具体知识、控制能力、识别质量、措施比例和因果关系分析。有效通知可以提高注意义务，但失去避风港不等于当然侵权。在权利人提供可靠特征、侵权反复发生且成本合理时，可以要求定向过滤；普遍监控则因误伤、成本和责任结构问题应保持例外。

### 3. 90 秒回答

> 生成式 AI 使“平台”成为过于粗糙的概念，模型开发者、开放权重者、API 服务者、生成平台和内容分发者的控制结构不同。崔国斌、王迁和孔祥俊提醒我们，算法相似识别不等于法律侵权判断，未满足安全港也不等于已经满足帮助行为、过错和因果关系；吴汉东、王杰则说明，持续控制数据和输出的平台不能机械适用被动存储规则。我的方案是七项责任矩阵：先看主体功能和行为参与，再看通知使平台获得何种知识、能够采取什么措施、识别准确率和误伤如何，最后判断因果与救济。权利人提供可靠指纹、侵权重复且成本低时，定向过滤具有正当性；但必须配套反通知、人工复核和错误恢复，不能把普遍监控变成默认义务。

### 4. 3 分钟展开顺序

1. 先区分六类平台主体；
2. 说明直接侵权、帮助侵权、安全港和通知规则的关系；
3. 比较能力匹配与算法中立路径；
4. 解释通知如何改变信息状态；
5. 给出个案删除—定向过滤—普遍监控的责任阶梯；
6. 加入权利人协力和用户程序保障；
7. 提出七项平台责任矩阵并作压力测试。

### 5. 高频追问

**问：平台没进避风港，为什么还不当然赔偿？**

> 安全港是责任限制结构。失去限制后仍要回到一般责任，证明帮助行为、过错、因果关系和损害。

**问：平台能识别相似内容，为什么还不能推定应知？**

> 相似识别通常不知道权属、授权、保护期和合理使用。技术能力会提高注意义务，但不能替代法律侵权信息。

**问：定向过滤与普遍过滤的界限是什么？**

> 定向过滤围绕特定作品、可靠特征、重复风险和有限范围；普遍过滤要求平台对所有内容主动判断，误伤、成本和责任扩张明显更高。

**问：商业秘密会不会让平台永远无法被审计？**

> 不应。可以向法院、监管者或受保密义务约束的审计者分层披露，通过抽样、统计和封闭审查验证措施，而不公开核心参数。

### 6. 容易失分的表达

- 不说“用了算法就不是中立平台”。
- 不说“没有避风港就一定侵权”。
- 不把通知删除当成独立请求权基础。
- 不把相似度识别等同于法律侵权判断。
- 不用“平台最有能力”替代成本、准确率和误伤分析。
- 不只谈权利人通知，不谈用户反通知和错误恢复。
