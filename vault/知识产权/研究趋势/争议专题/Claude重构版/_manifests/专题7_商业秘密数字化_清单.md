# 专题 7：商业秘密数字化、数据集合与算法透明

## 专题定位

本专题独立于专题 4（商业数据确权），专门研究**非公开数据**通过商业秘密法保护的路径及其数字时代边界。

### 与专题 4 的分工

| 维度 | 专题 4：商业数据确权 | 专题 7：商业秘密数字化 |
|------|---------------------|----------------------|
| **保护对象** | 公开/半公开商业数据 | 非公开数据、算法、模型参数 |
| **法律路径** | 数据权、弱权利、平台专有权、数据专条 | 商业秘密法、秘密性重构 |
| **核心争议** | 是否确权、权利强度、排他范围 | 集合秘密性、部分公开、反向工程 |
| **技术焦点** | 数据登记、可携权、必需开放 | 知识蒸馏、算法透明、分层披露 |

## 核心争议板块

### 争议 1：集合秘密性

**命题**：单条数据公开后，数据集合整体是否仍可主张秘密性？

**立场 A（崔国斌、陈兵等）**：
- 单条公开不等于集合整体容易获得
- 以集合边界、整体获取成本、替代成本判断
- 扩张解释"秘密性"以适应数据场景

**立场 B（限缩路径）**：
- 秘密性是商业秘密制度边界
- 不能用集合概念把公共信息重新封闭
- 应保留独立开发、合法拼接自由

**压力测试**：
- 若竞争者从合法公开来源独立重建同等数据集，商业秘密路径必须承认其合法
- 若其绕过访问控制整体复制实时数据库，纯公开论难解释控制措施意义

### 争议 2：AI 推导与"容易获得"

**命题**：AI 能从公开信息推导非公开结论时，"容易获得"标准如何调整？

**立场 A（冯晓青等）**：
- 行业 AI 推导能力应纳入判断
- 合理措施标准随技术能力提升
- 但合法使用公开数据训练不当然是不正当手段

**立场 B（技术中立）**：
- 不应因新技术出现而降低所有秘密保护
- 关键是竞争者实际获取路径
- 理论推导可能 vs 实际获取成本

### 争议 3：知识蒸馏是否合法反向工程

**命题**：通过合法 API 观察训练"学生模型"是否属于合法反向工程？

**立场 A（李昕梦）**：
- 合法 API 观察原则可进入反向工程
- 禁反向格式条款违约不当然构成侵权
- 审查目的、绕过措施、后续投入、直接替代

**立场 B（詹韫如）**：
- 须审查获取手段、使用方式、竞争损害
- 批量自动化调用可能构成不正当获取
- 商业秘密与合同、竞争法交叉适用

### 争议 4：算法透明 vs 商业秘密

**命题**：算法问责是否必须公开源代码，还是可以分层透明？

**立场 A（姚叶、衣俊霖、杨志航）**：
- XAI、举报人、第三方认证、技术标准提供受控透明
- 按风险和受领者区分披露范围
- 保护非必要商业秘密

**立场 B（全面透明）**：
- 算法影响公共利益时应优先透明
- 分层透明可能不足以支持有效问责

### 争议 5：商业秘密专条 vs 数据专条

**命题**：非公开数据适用商业秘密还是数据专条？

**立场 A（曹新明、叶悦）**：
- 数据专条保护交换价值（数据产品/服务）
- 商业秘密保护使用价值（非公开控制利益）
- 技术管理措施 ≠ 保密措施

**立场 B（侯利阳）**：
- 非公开数据适用商业秘密强保护
- 公开数据只在实质性替代时获竞争法弱保护
