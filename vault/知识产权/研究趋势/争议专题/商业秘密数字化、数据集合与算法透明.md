# 商业秘密数字化、数据集合与算法透明

> [!important] 分析边界
> “数据或算法有商业价值”“能够被控制”“满足商业秘密要件”“对方以不正当手段获取”“应当给予何种救济”是五个不同问题。不能因为著作权或专利不保护，就自动把对象转入商业秘密；也不能因为涉及透明或公共利益，就当然否定全部秘密性。

## 二、五组核心争议

### 1. 单条公开，数据集合是否仍可保密

- **支持集合层秘密性**：单项可查不等于集合整体易得；持续更新、清洗结构、访问控制和替代成本可能使集合仍不为公众普遍知悉。
- **限缩路径**：不能通过“集合”标签把公共信息重新封闭；合法从公开来源独立重建的同类集合应保持自由。
- **综合标准**：集合边界是否明确、整体是否可合法低成本获得、更新是否具有时间优势、措施是否真正控制访问而非单纯声明、被诉人是否整体搬运而非独立重建。

### 2. AI 能力是否改变秘密性判断

- **支持技术基准更新**：如果行业通用 AI 和普通算力可从公开材料稳定推导，信息可能已“容易获得”；权利人也应针对自动化攻击更新措施。
- **风险**：以最强模型能力作为基准会使秘密性随技术瞬间消失，也会给中小企业施加无限安全义务。
- **综合标准**：采用侵权发生时同领域合理技术能力、可获得算力、数据条件、成本与稳定复现概率，不以理论可能性代替现实可得性。

### 3. 知识蒸馏是不是合法反向工程

- **支持合法性**：从合法 API 输出观察模型规律，与传统黑盒反向工程相近；合同违约不当然满足商业秘密法的不正当手段。
- **限制合法性**：批量绕过速率限制、盗用账户、复制输出库或形成近乎完整替代，可能超出正常观察。
- **综合标准**：访问权源、绕过措施、查询规模、复制对象、后续研发投入、模型差异与市场替代应分别证明。

### 4. 算法透明是否要求放弃商业秘密

- **全面公开的缺陷**：源代码未必能解释模型决策，且会不必要地暴露核心竞争信息。
- **全面保密的缺陷**：高风险算法可能借商业秘密逃避歧视、合谋、安全与公共利益审查。
- **综合方案**：按受领者和风险分层——监管者受控披露、审计者保密验证、受影响者获得个案解释、公众获得风险与治理信息；配合保密令、第三方认证、技术标准和举报人免责。

### 5. 商业秘密应否成为其他知识产权失效后的兜底

- **支持补充**：算法、后台数据、训练配方和无独创性集合可能仍因秘密控制与开发投入值得保护。
- **反对自动兜底**：专利和著作权的保护条件也划定自由利用领域，不能只因不适格就改用商业秘密恢复排他。
- **综合标准**：商业秘密必须独立满足秘密性、商业价值、合理措施与不正当获取；保护范围受独立开发、反向工程、公共利益披露和竞争政策限制。

## 三、学术谱系与趋势

1. **传统阶段：静态秘密。** 以配方、文档和客户名单为典型，秘密／公开二分较清楚。
2. **平台数据阶段：集合秘密。** 研究开始区分单条与集合、数据内容与结构、底层数据与反爬措施。
3. **AI 阶段：动态秘密。** 算法、模型参数、训练配方和 AI 推导能力进入要件判断，保密措施转为技术、管理与合同的持续组合。
4. **当前阶段：保护与透明接口化。** 知识蒸馏、XAI、技术标准、举报人和受控披露使研究中心从“是否保密”转向“向谁、为何、披露多少以及披露后如何继续保密”。

## 四、面试立场

> 我支持商业秘密制度吸收非公开数据集合、算法和模型参数，因为其要件与反向工程例外比创设统一数据权更克制；但我会同时坚持三项修正：第一，单条公开不当然导致集合失密，集合投入也不当然封闭公共信息；第二，知识蒸馏和 API 观察须区分合同违约、不正当获取与市场替代；第三，高风险和公共利益场景采用受控、分层透明，而不是全公开或全保密。
