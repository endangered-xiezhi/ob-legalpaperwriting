# 法学论文整理SOP：Agent通用执行手册

> 本手册用于把一批PDF或TXT法学论文整理成质量稳定、可复核、可检索的结构化Markdown笔记，并进一步生成专题总览和交接记录。目标不是批量生成泛泛摘要，而是忠实还原每篇论文的研究问题、论证链条、证据和制度方案。

## 一、最终成果标准

完成一个论文合集后，应当至少形成四类成果：

1. 每份PDF对应一份经过核验的TXT或OCR文本。
2. 每篇独立论文对应一张结构化Markdown笔记。
3. 一份专题总览，反映论文、作者、年度、领域、趋势和理论张力。
4. 一份交接记录，说明已完成数量、异常文件、未决元数据和后续任务。

一篇“合格笔记”必须同时做到：

- 题名、作者、年份和刊物以原文为准。
- 原文摘要和原文关键词原样忠实转录，不自行改写或补造。
- 阅读范围覆盖摘要、引言、全部大小标题、核心论证、案例或数据、作者方案和结论。
- 能清楚回答作者提出了什么问题、如何分析、最终怎样解决。
- 作者观点与整理者概括严格区分，不把推测写成原文结论。
- 能被其他人从源PDF或TXT中快速复核。

## 二、不可违反的基本原则

### 2.1 全文阅读原则

不得只根据文件名、摘要、开头和结论生成笔记。至少必须核查：

- 首页或署名页；
- 中文摘要、英文摘要及关键词；
- 引言或问题提出；
- 全部一级、二级标题；
- 各部分核心论证段落；
- 重要案例、数据、图表、比较法材料；
- 制度建议和结论；
- 与作者、年份、项目来源有关的页眉、页脚或脚注。

### 2.2 原文忠实原则

- 不补充原文没有讨论的理论、案例、政策或价值判断。
- 不把整理者赞同的观点强化成作者结论。
- 不把作者介绍的反方观点误写为作者本人观点。
- 不为追求流畅而删除关键限定词，例如“原则上”“可能”“仅在……时”。
- 直接引用应尽量少；涉及准确表述时应回看原文，不依赖记忆。

### 2.3 元数据保守原则

- 文件夹名称只表示来源合集，不证明作者院校、师承或学术归属。
- 文件名末尾姓名不当然是唯一作者。
- 论坛、笔谈、会议纪要必须核验全部署名或参与者。
- 年份、刊物、期号无法确认时留空，并在 `warning` 中说明。
- 原文没有摘要或关键词时，明确写“原文未设摘要/关键词”，不得根据正文反推。

### 2.4 去重原则

正式创建笔记前，必须在整个目标知识库中按正式题名搜索。同一论文即使位于不同合集、使用不同破折号或文件名只列第一作者，也只能保留一份主笔记，通过 `collection` 记录多个来源合集。

### 2.5 可追溯原则

笔记应保留源PDF、源TXT、复核状态和异常说明。任何无法确认的信息都应暴露出来，而不是通过猜测填平。

## 三、开始前先建立任务合同

在处理文件前，先确定以下变量，并写进交接文档：

```text
合集名称：{COLLECTION}
PDF目录：{PDF_ROOT}
TXT目录：{TXT_ROOT}
论文笔记目录：{NOTE_ROOT}
知识库根目录：{VAULT_ROOT}
专题总览：{OVERVIEW_FILE}
交接文档：{HANDOFF_FILE}
预计PDF数量：{PDF_COUNT}
预计批次：{BATCH_PLAN}
每批数量：建议5—8篇
```

开始前还应确认：

1. 是否存在适用的 `SKILL.md` 或既有整理规范。
2. 知识库当前使用哪一版YAML字段。
3. 是否已有稳定的领域分类和研究路径。
4. 是否允许联网核对元数据；如允许，优先使用期刊官网、学校期刊平台和正式数据库页面。
5. 当前目录是否已有用户修改，避免覆盖既有笔记。

## 四、第一阶段：原始文件盘点

### 4.1 建立文件清单

统计PDF、TXT和其他文件数量，记录每份PDF的页数、文件大小和可提取字符量。推荐生成转换清单，至少包含：

| 字段 | 用途 |
| --- | --- |
| `source_pdf` | PDF完整路径 |
| `output_txt` | TXT完整路径 |
| `page_count` | 页数 |
| `char_count` | 总字符数 |
| `cjk_count` | 中文字符数 |
| `method` | 文字层提取或OCR |
| `warning` | 空白页、乱码、失败信息 |

不要依据文件数量直接认定论文数量。一份PDF可能是多人论坛、上下篇合刊、书评或会议发言合集；不同PDF也可能是同一论文的重复版本。

### 4.2 本知识库现有批量转换工具

在当前工作区可使用：

```bash
python3 "vault/知识产权/_tools/pdf_to_txt_batch.py" \
  --pdf-root "{PDF_ROOT}" \
  --out-root "{TXT_ROOT}" \
  --manifest "{TXT_ROOT}/_conversion_manifest.csv"
```

该脚本优先读取PDF文字层；文字过少时可调用本地OCR。其他环境没有该脚本时，可采用同样逻辑：先提取文字层，检测异常后再逐页OCR。

### 4.3 转换后的异常检测

必须检查：

- 页数很多但字符数异常少；
- 中文论文的 `cjk_count` 接近零；
- 文字中出现大量 `�`、错误字间空格或竖排错序；
- 摘要、关键词、标题或结论整体缺失；
- 表格和脚注挤入正文，导致语序混乱；
- 人名、法条号、年份、百分比、案号和英文案名乱码；
- 多人材料只提取出前几位发言人；
- PDF后半部分为空或重复前文。

可把文件划分为三类：

| 等级 | 判断 | 处理 |
| --- | --- | --- |
| A | 文字层完整，标题和正文可读 | 直接进入全文阅读 |
| B | 局部乱码、表格或脚注错序 | 结合PDF页面局部复核 |
| C | 大量空白、错字或文字层不可用 | 逐页OCR并记录复核说明 |

### 4.4 OCR复核要求

OCR完成不等于复核完成。至少要抽查：

- 第一页题名、作者、摘要和关键词；
- 每个一级标题所在页；
- 包含核心数据、法条或判例的页面；
- 结论页；
- 多人材料的目录、题名页和每次发言开头。

如一篇论文完全依赖OCR，`warning` 或 `review_note` 应说明页数和复核范围。

## 五、第二阶段：全库去重与元数据核验

### 5.1 去重搜索顺序

创建新笔记前依次搜索：

1. 完整正式题名；
2. 去除副标题后的主标题；
3. 题名中的连续关键短语；
4. 题名加第一作者；
5. 题名加完整作者组。

搜索时要统一识别：

- 中文或英文破折号；
- 直角引号、弯引号和书名号差异；
- 全角、半角标点；
- 冒号前后空格；
- 文件名下划线；
- “上”“下”或系列文章标识。

### 5.2 发现既有同题笔记时

- 不新建第二份笔记。
- 在原位置阅读全文复核。
- 保留原有合集，并把新合集加入 `collection` 列表。
- 修正错误作者、摘要、关键词和正文概括。
- 不因旧笔记存在就跳过全文核对。

### 5.3 元数据证据优先级

按以下顺序确认题名、作者、年份和刊物：

1. PDF首页、署名页或版权页；
2. PDF页眉、页脚、期刊目录信息；
3. 原文脚注中的作者和发表信息；
4. 期刊官网或正式学校期刊平台；
5. 权威数据库的文献页面；
6. 其他网页仅作线索，不单独作为最终依据。

外部网页与PDF冲突时，优先记录冲突并人工判断，不静默覆盖。

## 六、第三阶段：逐篇全文阅读方法

### 6.1 第一遍：建立结构地图

先完成以下记录：

```text
正式题名：
完整作者：
年份/刊物：
原文摘要：
原文关键词：
一级标题：
二级标题：
文章明确提出的核心问题：
结论中的主要方案：
```

这一遍的目标是识别文章骨架，不急于写通俗摘要。

### 6.2 第二遍：提取论证链

对每个主要标题回答四个问题：

1. 核心论点是什么？
2. 作者用什么理由、规范、数据或案例支持？
3. 作者反驳了谁或排除了什么方案？
4. 该部分在全文中承担提出问题、分析问题还是解决问题的功能？

建议形成简短证据表：

| 原文章节 | 作者论点 | 主要论据 | 案例/数据 | 三部归属 |
| --- | --- | --- | --- | --- |
| 引言 |  |  |  | 问题的提出 |
| 一、…… |  |  |  | 问题的分析 |
| 二、…… |  |  |  | 问题的分析/解决 |
| 结语 |  |  |  | 问题的解决 |

### 6.3 “提出—分析—解决”的归类标准

| 部分 | 通常包括 |
| --- | --- |
| 问题的提出 | 背景、制度困境、概念界定、文献争议、研究空白、研究问题 |
| 问题的分析 | 法解释、理论论证、比较法、历史研究、实证数据、案例评析、反方批判 |
| 问题的解决 | 解释论方案、立法建议、裁判规则、适用条件、限制、结论 |

不要机械按照原文前三章分配。一个标题可能同时包含分析和方案，应根据其主要功能归类，并保留原文逻辑顺序。

### 6.4 案例、数据和比较法材料

案例只需要写清：

- 案例名称或可识别信息；
- 与文章有关的核心事实；
- 作者引用它要证明什么。

实证论文还必须提取：

- 样本量和时间范围；
- 样本筛选条件；
- 核心变量或评价标准；
- 主要发现；
- 作者承认的局限。

比较法论文还必须区分：

- 外国制度的真实规则；
- 作者对外国制度的评价；
- 作者是否主张移植；
- 移植所需的体系条件和限制。

## 七、第四阶段：撰写单篇笔记

### 7.1 正文八段式固定结构

每篇笔记依次包含：

```markdown
# 论文正式题名

## 一句话主旨

## 原文摘要

## 原文关键词

## 通俗摘要

## 问题的提出

## 问题的分析

## 问题的解决

## 应试启发
```

### 7.2 各部分写作要求

#### 一句话主旨

- 1—2句话。
- 同时包含研究对象、核心判断和主要方案。
- 避免“本文主要研究了……”这类空泛表述。

#### 原文摘要

- 原文存在摘要时忠实转录，修复明显OCR断行但不改写内容。
- 原文没有摘要时写“原文未设摘要”。
- 会议实录或多人材料不得由整理者伪造“原文摘要”。

#### 原文关键词

- 只抄原文关键词栏。
- 不把题名词语或整理者标签补入本栏。
- 原文没有时写“原文未设关键词”，YAML中的 `original_keywords` 使用空数组。

#### 通俗摘要

- 建议150—350字。
- 用普通法学生能够理解的语言解释争议、作者判断及现实意义。
- 可以简化术语，但不能用夸张比喻歪曲作者立场。

#### 问题的提出

- 说明现实或规范背景、已有观点、作者发现的缺陷和真正研究问题。
- 应能回答“作者为什么要写这篇文章”。

#### 问题的分析

- 是全文最重要、通常最长的部分。
- 覆盖全部核心章节、主要论据、学说批判、数据和必要案例。
- 保留重要限定条件和反例。
- 不能只写结论清单而省略推理过程。

#### 问题的解决

- 写明作者的规则、制度或解释方案。
- 同时写适用前提、例外、程序、限制和风险控制。
- 作者没有完整方案时如实说明，不自行补齐。

#### 应试启发

- 将原文转换为课程论文、考研论述题或案例分析的可用框架。
- 必须从原文自然推导，不能添加作者未主张的答案。
- 建议写出可复用的分析顺序、区分标准或关键词。

### 7.3 便携最低YAML模板

在独立专题或尚未统一字段的知识库中，可使用：

```yaml
---
title: "论文正式题名"
author: "完整作者；多人用顿号分隔"
year: "年份"
journal: "刊物或正式文献类型"
collection: "合集名称"
field: "部门法或交叉领域"
trend_domain: "本专题主要上位领域"
research_area:
  - "子议题1"
  - "子议题2"
original_keywords:
  - "只抄原文关键词"
warning: "无法核实的信息；无则留空"
---
```

### 7.4 当前知识产权库扩展YAML模板

写入当前统一论文库时，优先使用现行字段：

```yaml
---
title: "论文正式题名"
author:
  - "作者甲"
  - "作者乙"
year: 2025
journal: "期刊名称"
collection:
  - "合集名称"
primary_domain: "著作权法"
cross_domains:
  - "反不正当竞争法"
research_paths: []
dialogue_role: []
trend_topics:
  - "稳定趋势专题"
research_area:
  - "具体子议题"
original_keywords:
  - "原文关键词"
author_affiliation: []
source_pdf: "/绝对路径/原文.pdf"
source_txt: "/绝对路径/原文.txt"
review_status: "fulltext_verified"
reviewed_at: "YYYY-MM-DD"
review_note: "说明本轮实际核验范围"
warning: ""
---
```

字段规则：

- `author`、`collection` 等多值字段统一使用列表。
- `primary_domain` 只选一个主要部门法；跨领域写入 `cross_domains`。
- `research_paths`、`dialogue_role` 只有在已有研究路径和对话关系证据时填写，不凭印象归类。
- `trend_topics` 使用既有稳定专题，具体概念放入 `research_area`。
- `review_status` 只能反映真实复核程度；没有全文阅读不得写 `fulltext_verified`。
- `review_note` 应说明是全文阅读、OCR复核、元数据复核，还是沿用既有成果。

两套模板不要混用。同一知识库已有统一字段时，应服从现有字段，而不是为单批论文另创体系。

## 八、特殊文献处理规则

### 8.1 多人论坛、会议实录和笔谈

- 核验全部署名、主持人、发言人和与谈人。
- `author` 按正式署名填写；参与者名单可在正文另列。
- 不把不同发言人的观点合并为全体共识。
- 先按议题归纳，再标明主要分歧和各自主张。
- 无统一摘要或关键词时明确留空。

### 8.2 扫描版和竖排文本

- 逐页OCR。
- 对题名、人名、标题、法条、案号、数据和结论重点人工复核。
- 无法识别的字句不要擅自补写，可保留警告并建议人工回看页码。

### 8.3 实证论文

- 不只写“数据表明”。
- 必须记录样本、变量、方法、发现和局限。
- 区分相关关系、回归结果和因果结论。
- 数字必须回到原文核对，避免OCR把小数点、百分号或样本量读错。

### 8.4 比较法论文

- 不把外国规则自动写成中国改革方案。
- 区分介绍、评价、借鉴和反对移植四种功能。
- 记录作者强调的制度背景和配套条件。

### 8.5 分上下篇、系列论文和转载

- 根据正式题名和独立发表信息判断是否分别建笔记。
- 同文转载只保留一张主笔记，并在合集或警告中记录版本。
- 上下篇各有独立摘要、结构和刊期时可以分开，但总览中应说明系列关系。

## 九、第五阶段：分批处理与批次验收

### 9.1 批次规模

建议每批5—8篇。主题相近的论文可放在同批，便于发现连续观点与分歧，但不得因为批量相似就套用同一摘要。

每批流程：

1. 确认待处理文件清单。
2. 全库去重。
3. 逐篇全文阅读并写笔记。
4. 自动检查字段和八个正文标题。
5. 人工抽查元数据、数据、案例和结论。
6. 更新专题总览和交接文档。
7. 汇报后暂停，等待下一批指令。

### 9.2 单篇验收清单

每篇完成后逐项确认：

- [ ] 正式题名与PDF一致。
- [ ] 完整作者已核验，多人材料无遗漏。
- [ ] 年份、刊物有原文或权威页面依据。
- [ ] 原文摘要没有被改写。
- [ ] 原文关键词没有被补造。
- [ ] 八个正文部分齐全且顺序正确。
- [ ] 全部主要标题已进入论证梳理。
- [ ] 主要案例或数据及其论证作用已体现。
- [ ] 问题的解决包含条件和限制，不只是口号。
- [ ] 应试启发能够从原文推出。
- [ ] `warning` 和复核状态反映真实情况。
- [ ] 全库没有同题重复笔记。

### 9.3 批次自动检查

可检查笔记数量、必需字段和八个标题：

```bash
find "{NOTE_ROOT}" -maxdepth 1 -type f -name '*.md' | wc -l

for f in "{NOTE_ROOT}"/*.md; do
  for h in \
    '## 一句话主旨' '## 原文摘要' '## 原文关键词' '## 通俗摘要' \
    '## 问题的提出' '## 问题的分析' '## 问题的解决' '## 应试启发'; do
    rg -q -F "$h" "$f" || echo "缺少 $h: $f"
  done
done
```

自动检查只能发现结构缺失，不能替代全文质量抽查。

### 9.4 每批至少抽查两篇

建议选择：

- 一篇文字层或元数据异常最多的文献；
- 一篇论证最复杂、数据最多或最能代表本批趋势的文献。

抽查时从笔记中的随机数据、案例和核心结论反向定位原文，确认不存在看似合理但无法在原文找到的内容。

## 十、第六阶段：专题总览

专题总览不是把每篇摘要拼起来，而是对全体样本进行二次归纳。至少包含：

1. 统计口径和合集边界。
2. PDF数、有效论文数、去重后数量和待处理数。
3. 全部论文总表。
4. 年度数量与作者分布。
5. 6—9个稳定上位领域。
6. 每个领域的代表论文、主要观点和演进方向。
7. 相反观点或理论张力。
8. 尚未形成趋势的孤立样本。
9. 适用于当前知识库的Dataview查询或索引链接。

### 10.1 领域归类规则

- 每篇只选择一个主要上位领域。
- 跨领域内容写入 `cross_domains` 或 `research_area`。
- 不因出现一个新术语就新建一个领域。
- 上位领域应能容纳至少2—3篇论文；只有1篇时可先列为孤立样本。
- 分类依据是论文的主要研究问题，不是作者身份或文件夹名称。

### 10.2 趋势与张力的区分

“趋势”需要至少两篇论文形成连续、互补或重复出现的主张。例如：

- 研究方法从规范解释转向实证检验；
- 救济政策从单纯提高赔偿转向精准补偿；
- 平台治理从结果责任转向能力、通知与介入程度的分层判断。

“理论张力”应呈现可比较的两端及真正争点。例如：

```text
全面强化惩罚性赔偿
vs.
仅对权利清晰、恶意显著的侵权类型化适用

真正争点：故意标准、权利不确定性、过度威慑和比例原则。
```

不要把同一作者的细微表述变化夸大成学术阵营，也不要把单篇观点写成稳定趋势。

## 十一、第七阶段：交接与批次汇报

### 11.1 交接文档必须记录

- 原始PDF、TXT、笔记和总览的完整路径；
- 原始数量、有效论文数量和去重情况；
- 已完成批次及剩余批次；
- 每批论文清单；
- 异常PDF和OCR处理情况；
- 元数据未决事项；
- 稳定领域；
- 下一批执行顺序；
- 禁止事项和验收标准。

### 11.2 每批汇报模板

```markdown
本批已完成：{N}篇；累计：{DONE}/{TOTAL}。

本批论文：
1. ……
2. ……

处理结果：
- 新建笔记：{N}
- 复核既有笔记：{N}
- 重复论文：{N}
- OCR复核：{N}
- 元数据待确认：{具体事项}

本批主要领域：……
主要趋势：……
主要理论张力：……
总览更新：……
建议人工抽查：论文甲、论文乙。
```

## 十二、常见失败模式

### 12.1 只读摘要就生成正文

结果是“问题的分析”缺少章节、论据和反方批判。必须读取全部标题和核心段落。

### 12.2 把文件名当元数据

常造成共同作者遗漏、刊物或年份错误。必须回到PDF首页和正式文献信息。

### 12.3 用同一套话批量生成

相近论文会出现几乎相同的通俗摘要和应试启发。每篇都要从独立论证链生成。

### 12.4 把外部知识混入作者观点

联网只能用于核对元数据或理解难点；外部观点不能静默写进“问题的分析”或“问题的解决”。

### 12.5 原文没有关键词却自行补充

分类标签可以写入 `research_area`，但不能冒充原文关键词。

### 12.6 OCR后不核对数字和人名

OCR最容易错在法条号、年份、小数点、案号和作者姓名，这些恰恰影响学术结论和元数据。

### 12.7 总览只做数量统计

合格总览还必须呈现领域内部的共同主张、演进方向、相反观点和孤立样本。

### 12.8 复核状态写得过高

只复核题名和摘要时不能标记为全文核验。复核状态必须诚实反映实际工作。

## 十三、质量评分表

每篇可按100分验收：

| 项目 | 分值 | 扣分情形 |
| --- | ---: | --- |
| 元数据准确 | 15 | 作者、年份、刊物未经核验 |
| 原文摘要与关键词 | 10 | 改写、补造或OCR错误 |
| 结构覆盖 | 15 | 遗漏主要标题或结论 |
| 论证链完整 | 25 | 只列观点，没有理由、批判和限定 |
| 案例/数据准确 | 10 | 数字、案名或作用错误 |
| 解决方案完整 | 10 | 遗漏条件、程序、例外或风险 |
| 通俗摘要与应试启发 | 10 | 空泛、夸张或脱离原文 |
| 可追溯与格式 | 5 | 路径、复核状态、警告或字段缺失 |

建议低于85分不得通过；出现作者错误、虚构摘要、核心结论反转或大段非原文内容时，无论总分多少均应退回重做。

## 十四、可直接交给其他Agent的完整提示词

将花括号内容替换为实际路径后使用：

```text
请按法学论文全文整理任务执行，不要只做摘要。

任务范围：
- 合集名称：{COLLECTION}
- PDF目录：{PDF_ROOT}
- TXT目录：{TXT_ROOT}
- 笔记目录：{NOTE_ROOT}
- 知识库根目录：{VAULT_ROOT}
- 总览文件：{OVERVIEW_FILE}
- 交接文件：{HANDOFF_FILE}

开始前：
1. 完整阅读适用的 legal-paper-analysis/SKILL.md 和本SOP。
2. 盘点PDF数量、页数和现有TXT，不要立即创建笔记。
3. 确认目标知识库现有YAML格式、稳定领域和是否存在同题笔记。
4. 给出批次安排，每批5—8篇；未经我说“继续”，每批汇报后暂停。

文本处理：
1. 先提取PDF文字层并生成转换清单。
2. 检查字符量、中文字符数、摘要、关键词、标题、结论和乱码。
3. 文字层异常的文献逐页OCR，并重点核对题名、作者、标题、数据、法条、案号和结论。

逐篇阅读：
1. 核验正式题名、完整作者、年份、刊物。
2. 阅读摘要、引言、全部大小标题、核心论证、案例或数据、制度建议和结论。
3. 将全部核心内容按“问题的提出—问题的分析—问题的解决”重新组织。
4. 严格区分作者观点、反方观点和整理者概括，不加入原文没有的理论或案例。

每篇正文必须依次包含：
1. 一句话主旨
2. 原文摘要
3. 原文关键词
4. 通俗摘要
5. 问题的提出
6. 问题的分析
7. 问题的解决
8. 应试启发

元数据规则：
- 只从原文关键词栏抄录 original_keywords；没有就留空并说明。
- 文件夹名称不代表作者院校或师承。
- 多人论坛、笔谈和会议实录不得遗漏共同作者或混淆不同发言人的观点。
- 无法核实的年份、刊物或作者信息不得猜测，写入 warning。
- 写入笔记前必须在整个知识库按正式题名去重；发现同题笔记时原位复核并增加合集属性，不重复创建。

批次验收：
1. 检查必需字段和八个正文标题。
2. 对每篇核对题名、作者、摘要、关键词、主要标题、案例/数据和结论。
3. 每批至少反向抽查两篇源文。
4. 更新总览中的进度、论文总表、年度、作者、稳定领域、趋势、理论张力和孤立样本。
5. 更新交接文件并报告本批清单、新建/复核数量、累计进度、OCR或元数据疑点、主要趋势以及建议抽查的两篇，然后暂停。

禁止：
- 不根据文件名直接生成元数据。
- 不只读摘要。
- 不补造原文摘要或关键词。
- 不把网页观点写成论文观点。
- 不为每个新术语创建新领域。
- 不覆盖用户已有修改。
- 不把未全文阅读的笔记标记为 fulltext_verified。
```

## 十五、最终完成条件

只有同时满足以下条件，才能宣布一个合集整理完毕：

- 源文件数量、有效论文数量和笔记数量已经对齐，并解释所有差异。
- 所有异常PDF均已处理或在警告中留下明确未决事项。
- 全库题名去重完成。
- 每篇笔记通过单篇验收。
- 专题总览已更新为最终数据。
- 交接文档标明完成批次和零待处理，或明确列出仍待人工处理的文件。
- 最终汇报包含实际论文清单、累计数量、领域、作者年份刊物、OCR或元数据疑点、趋势与理论张力、总览更新和建议抽查文献。

如果仍有无法读取的PDF、无法核实的作者或未完成的OCR，不应写“全部完成”，而应准确报告完成部分和阻塞事项。
