# 崔国斌：技术市场、版权、数据与专利

## 路径主旨

崔国斌习惯从技术过程、替代成本、平台控制能力和市场结构决定是否保护以及保护多宽。其论文跨越 AIGC、算法推荐、云存储、数据、商业秘密和 SEP，但共同问题是：规则是否准确回应实际技术控制与机会主义，而非被抽象权利概念带偏。

## 近五年推进

1. AIGC：审查提示、选择、修改与定稿是否对最终表达作出独创性贡献，并结合司法案例识别证据。
2. 平台版权：算法推荐不当然提高识别侵权能力，反对把技术介入机械转化为更高注意义务。
3. 数据与商业秘密：区分公开数据条目和集合、反爬措施与底层数据，提出企业数据的商业秘密吸收路径。
4. SEP：在国际诉讼中主张谨慎但对等的禁诉令，并维护权利人原则上的许可层级选择自由。
5. 救济：以替代成本解释商业秘密性，延续其技术和市场成本分析。

## 核心争议

- 与王迁：在人类创作底线上接近，但对用户通过生成流程形成表达贡献的可能性评价不同。
- 与蒋舸：都反对不必要的高识别成本；崔国斌更强调过程证据，蒋舸更强调最低门槛与后端调节。
- 与吴伟光：企业数据保护分别走向商业秘密与网络平台专有权，两者都不简单把原始数据直接绝对权化。
- 与孔祥俊：商业秘密路径与反不正当竞争法数据专条是竞争方案，也可能在不同数据形态上互补。

## 2026-07-23 增量推进

- AIGC 过程研究已自然延伸为“模型—服务—输出”分层：用户贡献解决输出权属，模型参数案件解决不当复制，服务商研究解决不同控制层级的责任。
- 此前 71 篇把训练技术过程拆成获取、准备、投喂、学习、模型和输出，并形成“不构成复制—非作品性使用—传播风险—公众接触概率”的竞争标准。这使崔国斌式技术分析不仅要说明发生了什么，还要说明该技术控制产生了何种机会主义和市场替代风险。
- 知识蒸馏和 API 获取说明模型能力相似、参数复制、商业秘密窃取与独立开发必须区分。
- 平台责任不再适合只争论中立或主动审查，应按开发、接入、生成和分发环节建立责任矩阵。
- 最适合继续研究：以技术控制、替代成本和证据能力为轴，构造五类主体的差异化义务，并把来源记录、输出抑制和可验证遗忘纳入救济矩阵。

## 2026-07-24 数据与商业秘密增量推进

- 51 篇新增论文强化了“单条数据—数据集合—数据结构—算法—模型参数—数据产品”的客体分层，印证不能由数据价值直接推出统一绝对权。
- 商业秘密仍适合非公开且受合理措施控制的数据集合，但公开或不满足秘密性的数据已有 2025 年新《反不正当竞争法》第 13 条第 3 款的行为法规制入口。
- 陈兵、林逸玲和林秀芹、王轩对“有限共享／部分公开”的研究支持集合层秘密性；侯利阳、曹新明与叶悦则要求保留公开数据、交换价值和独立利用空间，构成对商业秘密吸收路径的必要限缩。
- 知识蒸馏把反向工程推进到 API 和模型场景：合同违约、绕过技术措施、参数复制、能力相似和市场替代必须分别证明。
- 更新后的研究路径是“状态—行为—救济”三层模型：非公开集合优先商业秘密，公开数据优先专条行为审查，登记只形成可反驳的来源与结构证明。
