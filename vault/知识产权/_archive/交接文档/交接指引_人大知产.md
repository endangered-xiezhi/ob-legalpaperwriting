## 七、笔记属性与正文格式

### 7.1 YAML 属性

```yaml
---
title: "论文正式标题"
author: "原文完整作者；多人用顿号分隔"
year: "年份"
journal: "期刊或正式文献类型"
collection: "人大知产"
field:
  - "部门法或交叉领域"
trend_domain: "本专题统一上位领域"
research_area:
  - "2—4 个细分子议题"
original_keywords:
  - "只抄原文关键词栏"
warning: "无法核实或需要回看 PDF 的信息"
---
```

规则：

- `title` 以 PDF 正式题名为准，清除文件名下划线和保存时产生的异常符号。
- `author` 以论文正式署名为准；圆桌论坛和笔谈录不得只抄文件名第一人。
- `year`、`journal` 无法核实时留空，并在 `warning` 说明。
- `collection` 只表示该论文纳入本次合集，不证明作者院校。
- `field` 可写著作权法、商标法、专利法、商业秘密法、数据法、个人信息保护法、人格权法、知识产权基础理论等。
- `trend_domain` 只使用第八部分的稳定上位领域；不要把每个新概念都创建成一个领域。
- `research_area` 写 2—4 个具体子议题。
- `original_keywords` 只能来自摘要后的原文关键词栏；原文没有就留空并写明。
- 不新增 `teacher`、`school` 或“关联导师”。既有笔记中的相关字段只有在原库仍有其他用途时才保留；明显错误的必须纠正。

### 7.2 标签与统一领域链接

属性下面保留简洁标签：

`#部门法 #统一领域 #原文关键词`

不单独建立关键词页面。正文不写“关联导师”，只写：

`统一领域：[[专题/人大知产/人大知产研究总览#对应上位领域|对应上位领域]]`

### 7.3 正文顺序

1. 一句话主旨。
2. 原文摘要。
3. 原文关键词。
4. 通俗摘要。
5. 问题的提出：Markdown 思维导图式项目符号，末尾附一句话概括。
6. 问题的分析：纳入全部主要大小标题、学说批判、主要论据、数据和必要案例，末尾附一句话概括。
7. 问题的解决：纳入作者方案、规则构造、适用条件、限制和结论，末尾附一句话概括。
8. 申请启发或应试启发。

“通俗摘要”可以口语化，但不得戏谑作者、虚构学派标签或把复杂论证改写成夸张比喻。“申请启发或应试启发”必须由原文观点自然推导，并与人大知识产权法学习、考研、课程论文或案例分析有关。

## 十一、专题总览结构

`人大知产研究总览.md` 至少包含以下内容：

1. 统计口径和完成进度。
2. 31 篇论文总表。
3. 年度数量分布。
4. 作者与共同作者分布。
5. 八个上位领域的数量、作者和论文。
6. 各领域的主要研究问题和规则方案。
7. 相反观点与理论张力。
8. 尚未形成趋势的孤立样本。
9. OCR、元数据或分类待核实事项。
10. Dataview 自动聚合表格。

总表查询应兼容单值和列表形式的 `collection`：

```dataview
TABLE WITHOUT ID rows.file.link[0] AS 论文, rows.author[0] AS 作者, rows.year[0] AS 年份, rows.trend_domain[0] AS 上位领域
FROM "知识产权"
WHERE contains(collection, "人大知产") AND title
GROUP BY title
SORT rows.year[0] DESC, rows.author[0] ASC
```

各领域表格可使用：

```dataview
TABLE WITHOUT ID year AS 年份, file.link AS 论文, author AS 作者, research_area AS 子议题, original_keywords AS 原文关键词
FROM "知识产权"
WHERE contains(collection, "人大知产") AND trend_domain = "对应上位领域"
SORT year DESC, author ASC
```

总览中的“趋势”必须在读完相应论文后归纳，不能根据题目数量直接推断。只有一篇支持的观点应列为“孤立样本”或“待观察议题”，不能写成稳定趋势。

## 十二、质量底线

- 原文摘要可以清理断行、OCR 空格和页眉页脚，但不得改写或概括后冒充原文摘要。
- 原文关键词只能来自摘要后的关键词栏；没有就留空并写明。
- 年份、期刊、作者、共同作者无法核实时留空并加入 `warning`，不能补猜。
- 每篇必须阅读摘要、引言、全部大小标题、核心论证段落和结论；有案例或比较法材料的，还须阅读其具体用途。
- 不得根据题目、文件名和自动关键词机械生成“提出—分析—解决”。
- 不得为迎合应试用途虚构“人大方案”“某导师观点”或未被作者论证的结论。
- 多人笔谈或圆桌论坛必须区分不同发言人的观点，不得强行合并成单一作者立场。
- 既有笔记不是当然正确；发现原摘要改写、作者错误、导师化叙述、过度口语化或原文无依据内容时，应回到 PDF 重写。
- 上位领域保持 6—9 个稳定分类；跨领域论文只选一个主要领域，其他内容写入 `research_area`。
- 每批 7—8 篇只是新的工作节奏，不降低单篇阅读标准。
- 每批结束后至少抽查 2 篇：优先抽查最长论文、OCR 警告论文、多人笔谈或既有重复笔记。
- 发现 OCR、作者、摘要或分类问题时，应回改同批甚至前批已经生成的笔记，并同步更新总览统计。
